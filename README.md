# Анализатор Unicode и UTF-8

Настольное приложение на Python и PyQt6 для исследования текста: от видимого символа до кодовых точек и байтов UTF-8.

Приложение помогает увидеть, почему один отображаемый символ может состоять из нескольких кодовых точек и занимать несколько байтов. Например, буква с комбинируемым знаком и составной эмодзи выглядят как один символ, но имеют разное внутреннее представление.

## Возможности

- Вывод байтов введённого текста в шестнадцатеричном виде.
- Подсчёт расширенных графем и байтов UTF-8.
- Просмотр графемы справа от курсора и её порядкового номера.
- Вывод кодовых точек, Unicode-имён и категорий для каждой части графемы.
- Преобразование введённого кода в символ с его характеристиками.
- Проверка формата кода, диапазона Unicode и запрет ввода суррогатных кодовых точек.
- Подсветка строк, в которых нет печатных кодовых точек по критерию Python `str.isprintable()`.
- Добавление и настройка шрифтов через конфигурационный файл без изменения кода программы.
- Вывод семейств шрифтов, фактически использованных Qt для отображения первой графемы в поле символа.
- Очистка полей одной кнопкой.

## Примеры

| Текст | Графемы | Кодовые точки | Байты UTF-8 |
|---|---:|---|---|
| `A` | 1 | `u+0041` | `41` |
| `Я` | 1 | `u+042f` | `d0 af` |
| `😀` | 1 | `U+01f600` | `f0 9f 98 80` |
| `é` — `e` + комбинируемое ударение | 1 | `u+0065, u+0301` | `65 cc 81` |
| `👩‍💻` | 1 | `U+01f469, u+200d, U+01f4bb` | `f0 9f 91 a9 e2 80 8d f0 9f 92 bb` |

Для выделения расширенных графем используется шаблон `\X` библиотеки `regex`. Поэтому счётчик символов учитывает графемы, а не просто результат `len(text)`.

## Формат ввода кодовой точки

В приложении используется собственный формат фиксированной длины:

| Префикс | Количество hex-цифр | Пример |
|---|---:|---|
| `u+` | 4 | `u+042F` → `Я` |
| `U+` | 6 | `U+01F600` → `😀` |

Регистр букв внутри шестнадцатеричного числа не имеет значения. Регистр префикса определяет требуемую длину записи. Длинная запись также допускает значения из BMP: например, `U+000041`.

Фиксированная длина позволяет обработать ввод сразу после последней цифры, без кнопки подтверждения. При неполном вводе результат очищается; часть ошибок формата определяется только после достижения полной длины.

При выводе точки BMP записываются с префиксом `u+`, остальные — с `U+`; hex-буквы выводятся в нижнем регистре. Этот формат отличается от стандартного обозначения Unicode и от escape-последовательностей Python.

Поле кода принимает одну кодовую точку. Для составной графемы приложение выводит список её кодовых точек, но обратный ввод такого списка не поддерживается.

## Настройка шрифтов

Шрифты загружаются при запуске из каталога `fonts/`. Их список задаётся в файле `fonts/fonts_list.txt` в формате JSON. Чтобы добавить шрифт, не требуется менять исходный код программы:

1. Поместите файл шрифта, например `.ttf` или `.otf`, в каталог `fonts/`.
2. Добавьте запись в JSON-массив в `fonts/fonts_list.txt`.
3. Перезапустите приложение.

Пример конфигурации с основным текстовым шрифтом, дополнительным текстовым шрифтом и шрифтом эмодзи:

```json
[
  {
    "font_family": "JetBrains Mono",
    "font_name": "JetBrainsMono-Regular.ttf",
    "is_main": true
  },
  {
    "font_family": "Noto Sans",
    "font_name": "NotoSans-Regular.ttf"
  },
  {
    "font_family": "Noto Color Emoji",
    "font_name": "NotoColorEmoji.ttf",
    "is_emoji": true,
    "is_main": true
  }
]
```

| Поле | Назначение |
|---|---|
| `font_family` | Имя семейства внутри файла шрифта; должно совпадать с семейством, которое сообщает Qt |
| `font_name` | Имя файла в каталоге `fonts/` |
| `is_emoji` | `true` для шрифта эмодзи; по умолчанию `false` |
| `is_main` | `true` для основного шрифта своей группы; по умолчанию `false` |

В каждой группе — текстовые шрифты и шрифты эмодзи — должен быть ровно один основной шрифт. Он ставится первым в списке предпочтительных семейств; остальные сохраняют порядок из конфигурации. Qt выбирает шрифт для конкретных глифов с учётом доступности символов и механизма подстановки шрифтов (fallback).

При запуске проверяются формат конфигурации, успешность загрузки каждого файла и наличие заявленного семейства в загруженном шрифте. Системная установка файлов шрифтов не требуется: приложение регистрирует их через Qt.

## Информация о применённом шрифте

Поле шрифтов (`txt_char_fonts`) показывает имена семейств, фактически использованных Qt при отображении первой графемы в поле символа. Данные определяются по результату разметки текста и его `glyphRuns`, а не только по настройке основного шрифта.

Если Qt использовал несколько семейств для частей составной графемы, они выводятся через запятую, без повторов и в алфавитном порядке. Поэтому для буквы и эмодзи могут отображаться разные семейства, а результат может отличаться от основного шрифта в конфигурации.

Информация обновляется при изменении символа, вводе кодовой точки и выборе графемы курсором в исходном тексте. Если в поле символа введено несколько графем, список шрифтов относится только к первой из них.

## Технологии и реализация

- **Python** — логика приложения.
- **PyQt6 / Qt Widgets** — интерфейс и обработка событий.
- **Qt Creator / Designer** — форма `unicode.ui`.
- **unicodedata** — имена и категории кодовых точек.
- **regex** — выделение расширенных графем.
- **Pydantic** — проверка конфигурации шрифтов.
- **pytest, pytest-qt** — модульные и интерфейсные тесты.
- **pytest-cov** — отчёт о покрытии.

Операции с Unicode вынесены в отдельный класс, не зависящий от Qt. Класс окна отвечает за отображение данных и обработку сигналов. При взаимном обновлении полей используется `QSignalBlocker`, а временный флаг преобразования сбрасывается через `finally`.

Пути к форме и шрифтам вычисляются относительно расположения исходного файла, поэтому загрузка ресурсов не зависит от рабочего каталога процесса.

## Установка и запуск

Требуется Python 3.12 или новее и PyQt6 с Qt 6.9 или новее. Команды ниже предназначены для Windows и выполняются из корня проекта.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install "PyQt6>=6.9" regex "pydantic>=2" pytest pytest-qt pytest-cov
```

В корне проекта должны находиться `unicode.ui` и каталог `fonts/` с конфигурацией `fonts_list.txt` и всеми файлами шрифтов, перечисленными в ней. Состав шрифтов можно менять по инструкции в разделе «Настройка шрифтов».

Запуск приложения:

```powershell
.venv\Scripts\python.exe src\unicode.py
```

В PyCharm в конфигурации запуска нужно указать `src/unicode.py` как Script path. Для разрешения импортов в редакторе можно отметить `src` как Sources Root.

## Тестирование

Запуск тестов:

```powershell
.venv\Scripts\python.exe -m pytest tests -v
```

Либо запуск с отчётами покрытия:

```powershell
.\run_tests.bat
```

`pytest.ini` не требуется. `conftest.py` подключает каталог `src` и создаёт окно для интерфейсных тестов без обязательной загрузки шрифтов. Отдельные тесты проверяют реальные шрифты, если их файлы доступны.

Проверяются преобразования UTF-8, составные графемы, границы Unicode, полный и неполный ввод кода, обновление данных при редактировании и перемещении курсора, блокировка сигналов, очистка полей и запуск приложения. Отдельная проверка подтверждает загрузку формы из другого рабочего каталога.

После запуска через `.bat` формируются:

- `reports/htmlcov/index.html` — HTML-отчёт о покрытии;
- `reports/junit.xml` — результаты в формате JUnit XML.

При проверке версии с каталогом `src` в Linux, Python 3.12 и Qt 6.11: **154 теста прошли, 3 пропущены** из-за отсутствия файлов шрифтов. Запуск самого `.bat` в Windows в эту проверку не входил.

## Ограничения

- Наличие имени и кода символа не гарантирует его отображения: для этого нужен подходящий глиф в доступных шрифтах.
- Позиции курсора на границах графем обрабатываются; для позиции внутри составной графемы выбор содержащей её графемы не гарантируется.
- При вводе нескольких графем в поле символа появляется предупреждение, но характеристики введённой строки всё равно выводятся.
- Приложение исследует текст и не выполняет его автоматическую нормализацию.
